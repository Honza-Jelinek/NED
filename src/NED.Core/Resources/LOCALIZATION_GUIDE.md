# NED.Core Localization Guide

Instructions for replacing hardcoded UI strings with `IStringLocalizer<Strings>` calls.

## Infrastructure (already set up)

- **Resource files:** `Resources/Strings.resx` (EN default), `Resources/Strings.cs.resx` (Czech)
- **Marker class:** `Resources/Strings.cs`
- **DI:** `AddLocalization()` registered in `ServiceCollectionExtensions.cs` — do NOT set `ResourcesPath`, the marker class namespace already resolves correctly
- **Global usings:** `Microsoft.Extensions.Localization` and `NED.Core.Resources` in `_Imports.razor`
- **Language menu:** auto-generated by `LanguageRegistry` (scans satellite assemblies) → Window → Language submenu with SVG flags

## Adding a new language

1. Create `Resources/Strings.<culture>.resx` (e.g. `Strings.de.resx`) with all keys translated.
2. Add a flag SVG at `wwwroot/flags/<culture>.svg` (e.g. `de.svg`). Missing → globe fallback.
3. Optionally add the native name to `NativeNameFor()` in `Resources/LanguageOption.cs` (otherwise `CultureInfo.NativeName` is used).

The language appears in the menu automatically — no other code changes.

## Key naming convention

Use `Section_Action` format. Examples:

| Key | EN value | CS value |
|-----|----------|----------|
| `File_New` | New | Nový |
| `File_Save` | Save | Uložit |
| `Dialog_Cancel` | Cancel | Zrušit |
| `ManageLibraries_Title` | Manage Libraries | Správa knihoven |
| `ManageLibraries_NoLibrary` | No library yet. | Zatím žádná knihovna. |

Use the component/dialog name as prefix where it makes sense. For shared strings (Cancel, Close, OK), use no prefix.

## Replacement loop

For each `.razor` component listed below, repeat this loop:

### Step 1 — Inject the localizer

If the component does not already have it, add this line near the top (after `@inject` directives or after `@namespace`):

```razor
@inject IStringLocalizer<Strings> Loc
```

### Step 2 — Find hardcoded strings

Search for these patterns in the component:

- `Label="..."` attributes (MudBlazor)
- `Placeholder="..."` attributes
- `Title="..."` attributes
- Text content inside tags: `<MudButton>Text here</MudButton>`
- `<MudText>Text here</MudText>`
- Tooltip strings
- String literals in `@code` blocks shown to the user

Ignore: CSS class names, enum values, technical identifiers, file extensions.

### Step 3 — Add resource entries

For each hardcoded string, choose a key and add an entry to **both** files:

**In `Resources/Strings.resx`** (EN default):
```xml
<data name="File_SaveAs" xml:space="preserve"><value>Save As…</value></data>
```

**In `Resources/Strings.cs.resx`** (Czech):
```xml
<data name="File_SaveAs" xml:space="preserve"><value>Uložit jako…</value></data>
```

### Step 4 — Replace the string

**Simple attribute:**
```razor
<!-- Before -->
<MudMenuItem Label="Save">
<!-- After -->
<MudMenuItem Label="@Loc["File_Save"]">
```

**Tag content:**
```razor
<!-- Before -->
<MudButton>Cancel</MudButton>
<!-- After -->
<MudButton>@Loc["Cancel"]</MudButton>
```

**Interpolated string (with variables):**
```razor
<!-- Before -->
<MudText>Indexováno: @Index.Entries.Count assetů</MudText>
<!-- After — use format string -->
<MudText>@string.Format(Loc["ManageLibraries_IndexedCount"], Index.Entries.Count)</MudText>
```
And in .resx: `Indexed: {0} assets` / `Indexováno: {0} assetů`

**String in @code block:**
```csharp
// Before
var title = "New Graph";
// After
var title = Loc["NewGraph_Title"].Value;
```

### Step 5 — Verify

After processing each component, run `dotnet build src/NED.Core` to confirm no errors.

### High priority — main UI surfaces

## Edge cases

- **MudBlazor `Label` attribute** expects `string`, so `@Loc["Key"]` works directly (implicit conversion from `LocalizedString` to `string`).
- **Multi-line or paragraph text** — use a single key for the whole block, not one key per sentence.
- **Strings that contain markup** (`<code>`, `<br/>`) — extract the text parts only; keep HTML in the Razor template. If the entire block must be localized with markup, use `@((MarkupString)Loc["Key"])`.
- **Do not localize** technical terms like "NED", "subgraph", file format names (`.nedgraph.json`), or node type names that come from code reflection.
